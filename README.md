# wows-helper · 战舰世界助手（使用手册）

> 在群里发 `@机器人 wws 大和`，机器人会把这个账号（或这条船）的战绩**渲染成图片发出来**，
> 并顺口说一句人话。

这份文档是**给使用者看的**：怎么装、怎么开、群里怎么用、设置项是什么意思、出问题先看哪里。

> 想改代码、或想了解"为什么这样设计 / 上游有哪些坑 / 怎么跑自检"，
> 请看 [`DEVELOPMENT.md`](DEVELOPMENT.md)（开发文档）。

## 1. 安装

### 1.1 你需要准备

| 项目 | 要求 |
|---|---|
| 系统 | Windows 10 / 11 |
| Python | **3.11 或更高**（3.13 / 3.14 实测可用）。没装的话去 <https://www.python.org/downloads/> 下载，安装时**勾选 "Add python.exe to PATH"** |
| yuyuko 凭据 | 格式为 `账号ID:Token`，向 yuyuko 官方群（967546463）申请 |
| 磁盘 | 约 1 GB（含 chromium 与舰船图缓存） |
| 网络 | 能访问 GitHub、yuyuko 接口与阿里云 OSS |

### 1.2 第一步：启动桥接服务

在插件目录里**双击** `启动桥接服务.bat`。

首次运行会**自动完成**下面这些事，全程需要几分钟（取决于网速）：

1. 下载 Hikari-core-v2 源码
2. 安装 Python 依赖（约 145 MB）
3. 下载 chromium 渲染内核（约 600 MB）

之后每次启动都是秒开（依赖已就绪时会跳过安装）。

窗口里会出现一行提示，问你要 yuyuko 凭据：

```
yuyuko API credential (format: accountID:Token)
  Paste it here (or press Enter to skip)
```

直接粘贴你的 `账号ID:Token` 回车即可；**按回车跳过也行**，稍后在 QQ Agent 的设置页里填
（这条路不用重启桥接服务）。

> 无人值守部署可以绕开交互，直接给启动参数：
> `启动桥接服务.bat -Token "账号ID:Token"`。

**这个窗口要一直开着。** 关掉窗口 = 关掉服务，群里的 `wws` 指令就会报
"数据服务没启动"。可以把它最小化，或参考 [1.4](#14-让它开机自动运行可选) 做成自动启动。

### 1.3 第二步：在 QQ Agent 里启用插件

1. 打开 QQ Agent → **「插件」** 页
2. 找到 **战舰世界助手** —— 本插件出于安全考虑**默认关闭**，需要手动开启
3. 点启用；再进它的「设置」，确认两项：
   - **Hikari 桥接服务地址** = `http://127.0.0.1:8788`（默认值，端口没改过就不用动）
   - **yuyuko API 凭据** = 你的 `账号ID:Token`（没在启动窗口里填的，**这里必须填**）

**核对是否装好**：浏览器打开 <http://127.0.0.1:8788/health>，看到
`"ready": true` 说明桥接正常；`"token_configured": true` 说明凭据已就位。

### 1.4 让它开机自动运行（可选）

桥接服务就是一个普通命令行程序，二选一：

- **手动**：每次开机双击 `启动桥接服务.bat`（最省事）
- **自动**：用「任务计划程序」新建"登录时运行"的任务，程序填 `powershell`，
  参数填 `-NoProfile -ExecutionPolicy Bypass -File "<插件目录>\bridge\start-bridge.ps1"`

## 2. 在群里怎么用

### 2.1 基本用法

```
@机器人 wws 大和
```

**两个条件必须同时满足**，缺一个都不会响应：

1. **@ 了机器人本人**（@ 别人不算）
2. **去掉 @ 之后，第一个词是 `wws`**

这样设计是因为群里"@ 别人 + 随手打一句话"太常见，宁可不响应也不要乱响应。

### 2.2 查别人（不用绑定）

把名字换成对方的**游戏昵称**或**游戏 ID**：

```
@机器人 wws 大和 China_Player
@机器人 wws 大和 12345678
```

第一条查的是名为 `China_Player` 的账号，第二条查的是游戏 ID 为 `12345678` 的账号。

### 2.3 一条指令匹配到多个结果时（需要选序号）

如果匹配到多个账号或船只，机器人会**直接把一张选择列表图发进群**，
然后在文字里提醒你回序号：

```
（群里出现一张选择列表图）
机器人：@你 看图回个序号，1 还是 2
```

回复时**也要 @ 机器人**：

```
@机器人 1
```

`1` / `选 1` / `第1个` 都能识别。回复后机器人会**直接把图发出来**。

> 两个候选同名时（例如同一昵称下有两艘同名船）是正常的，照序号选即可。

> 为什么要 @：群里连着两句"1""2"太常见，不加 @ 无法确认是在回答机器人。
> 觉得碍事的话，可以在设置里关掉「必须 @ 机器人才响应」。

### 2.4 会话记忆

- 序号选择保留 **5 分钟**，超时后重新发一次 `wws` 指令即可。
- 查询结果会进上下文，所以机器人能接着聊"这船胜率不错啊"之类的话。

## 3. 全部指令

都是 `@机器人 wws <命令>` 的形式。常用的几类：

| 你想干什么 | 指令 |
|---|---|
| 查账号总水表 | `wws me` |
| 查指定服务器的账号 | `wws me asia` |
| 查某条船的水表 | `wws ship 大和` |
| 查最近 30 天战绩 | `wws recent 30` |
| 查最近的战斗记录 | `wws recents 7` |
| 查军团信息 | `wws clan <军团名>` |
| 查排位 / 军团战 | `wws cw.rank asia` |
| 查绑定的账号列表 | `wws bind_list me` |
| 查帮助（图） | `wws help` / `wws 帮助` |

> 完整命令表见上游项目
> [Hikari-core-v2 README](https://github.com/wows-yuyuko/Hikari-core-v2/blob/main/README.md)。
> 本文只列常用的，实际支持的命令远不止这些。

**写错了也没关系**：`wws` 后面接不认识的内容时，机器人会回一张写着正确写法的帮助图。

## 4. 设置项说明

位置：QQ Agent →「插件」→ 战舰世界助手 →「设置」。

### 4.1 最常用的几项

| 设置项（界面上的名字） | 默认 | 说明 |
|---|---|---|
| **Hikari 桥接服务地址** | `http://127.0.0.1:8788` | 桥接服务在哪。没改过端口就别动 |
| **yuyuko API 凭据（必填）** | 空 | 格式 `账号ID:Token`。在启动窗口里填过的话，这里可以留空 |
| **出图格式** | `jpeg` | `jpeg` 体积最小；`png` 更清晰但更慢更大 |
| **渲染浏览器** | `chromium` | 一般不用改，它比 firefox 快约 3 倍 |
| **缓存目录（game_path）** | 空（用默认） | 想换磁盘位置时填，路径里**不要有中文和空格** |
| **访问 WG 的代理** | 空 | 只有访问 WG 需要代理时才填，如 `http://127.0.0.1:7890` |
| **桥接服务口令** | 空 | 只在启动桥接时带了 `--access-token` 才需要填，两边必须一致 |
| **指令语言** | `zh` | 指令提示 / 帮助页的语言（`zh` / `en`） |

### 4.2 行为相关的

| 设置项（界面上的名字） | 默认 | 说明 |
|---|---|---|
| **必须 @ 机器人才响应** | 开 | 关掉后任何以 `wws` 开头的消息都会被响应，**群里容易误触发** |
| **把渲染图直接发到群里** | 开 | 建议保持开启：模型看不到图片内容，关掉后它常常什么都不发 |
| **查询超时（毫秒）** | 60000 | 一次查询通常 5~10 秒，首次运行会久一些。网络慢可以调大 |
| **把查询数据注入上下文** | 开 | 关掉后模型只拿到"有图"的提示，接话会比较空 |
| **注入数据上限（字符）** | 1600 | 防止超长水表撑爆提示词 |
| **发图时 @ 触发者** | 开 | 发图时顺带 @ 一下提问的人 |
| **发图时引用触发消息** | 开 | 发图时引用那条 `wws` 消息，群里更清楚在回谁 |
| **多选会话保留数** | 6 | 群里同时有多个人在选序号时的上限（保留 5 分钟） |
| **调试日志** | 关 | 排查问题时打开：会记录认领了哪条指令、耗时、图片大小 |
| **启用 HTTP/2** | 开 | 一般不用动 |
| **自动套用模板 / 自动截图出图** | 开 | 关掉就不出图了，只回文字，一般不要关 |

### 4.3 图片服务

渲染好的图会暂存在本地，通过一个**只读**的小服务提供给协议端：

| 设置项（界面上的名字） | 默认 | 说明 |
|---|---|---|
| **启动本地图片服务** | 开 | 协议端与机器人同机时建议开启 |
| **图片服务监听地址** | `127.0.0.1` | 只有协议端在别的机器上时才需要改 |
| **图片服务端口** | 32801 | 被占用时插件会自动降级，不影响使用 |
| **渲染图保留时长（秒）** | 600 | 超时自动删除 |
| **渲染图体积上限（MB）** | 12 | 超过则跳过发送，只在文字里说明 |

> 发图会依次尝试三条路：**本地文件 → 本地图片服务 URL → base64 内联**。
> 三条都失败才会报"发送失败"。

### 4.4 高级

| 设置项（界面上的名字） | 默认 | 说明 |
|---|---|---|
| **钩子内预取数据（默认关闭）** | **关** | **不建议打开**。钩子只有 5 秒上限而查询要 5~10 秒，预取几乎必然超时，只会让每次 `@wws` 白等几秒再退回正常流程 |
| **预取超时（毫秒，仅在预取开启时生效）** | 3600 | 仅在上面的预取开启时有意义，必须小于 4500 |
| **强制覆盖 PlatformId** | 空 | 一般不用填 |
| **BotId** | `0` | 机器人自身标识，上游必填项 |

**触发词**（`triggerKeywords`）在设置页里是只读的说明项，想改要去编辑
`data/config.json` 里该插件的这一项。

**禁用某些写操作**：想关掉改绑定之类的功能，启动桥接时加参数：

```
启动桥接服务.bat -IgnoreList "set_BindInfo,change_BindInfo,delete_BindInfo"
```

> ⚠️ 必须填**函数名**（`set_BindInfo`），不能填指令词（`bind`）—— 填错会**静默失效**，
> 看起来禁用了其实没禁。

## 5. 常见问题

| 现象 | 怎么办 |
|---|---|
| **完全没反应** | 依次确认：① 插件已启用；② @ 的是机器人本人；③ `wws` 是第一个词；④ 打开「调试日志」看有没有"认领指令"的记录 |
| **回"还没有配置 yuyuko API 凭据"** | 在插件设置页填 `账号ID:Token`。填完**不用重启**，下一条指令即生效 |
| **回"桥接服务没启动或地址不对"** | 启动窗口被关了。重新双击 `启动桥接服务.bat`，并核对设置里的端口是 8788 |
| **回"响应超时"** | 先访问 <http://127.0.0.1:8788/health> 确认 `ready: true`；首次查询要下载浏览器和船图（几分钟），把「查询超时」调大些再试 |
| **只有文字、图发不出来** | 看启动窗口有没有"渲染图自动发送失败"；协议端与机器人不在同一台机器时，把「图片服务监听地址」改成协议端能访问的地址 |
| **@ 别人时机器人不响应** | 设计如此（只认 @ 机器人本人的消息） |
| **回复数字没续查** | 回复也要 @ 机器人，写成 `@机器人 1` |
| **回复序号后没有图、又让你选一次** | 两种可能：① 插件没重载（见下表最后一条）；② 桥接在跑旧代码 —— **重启桥接服务**（新版已修好"首次查别人、再回序号"这个组合）。重启后如果恢复，说明就是它 |
| **重复发同一张图** | 确认「把渲染图直接发到群里」是开着的；插件本身也有去重 |
| **提示"该功能已被禁用"** | 部署者用 `-IgnoreList` 关掉了这个写操作 |
| **机器人只回一句空话、没有数据** | 打开「调试日志」看是否发起了查询；也可能是模型没调用工具，重发一次指令 |
| **改了插件文件却不生效** | QQ Agent 只在**启用插件时**加载一次入口文件。改完 `index.js` 要回「插件」页把本插件关掉再打开 |

打不开 `/health` 时，先看启动窗口里有没有 `ready=false` 与 `core_error` 字段 ——
那说明依赖没装好，重新运行一次 `启动桥接服务.bat` 即可（它会检测到并补装）。

## 6. 启动窗口里的日志怎么看

大部分"看起来像崩溃"的日志其实**可以忽略**。记住这张表就够了：

| 日志 | 要不要管 |
|---|---|
| `WARNING 未加载 data_user 私有模块…` | **忽略**（那是上游的可选模块） |
| `WARNING 模板清单检查临时失败，已跳过本次模板更新…` | **忽略**。模板早就装好了，图照出；下次启动或定时任务会自动重试 |
| `INFO 页面 networkidle 未在 2000ms 内达成…继续渲染` | **忽略**。只是外部图标资源慢，页面本身正常 |
| `INFO 管理员校验串已生成（请私信发送给机器人）：…` | 只在你需要用管理指令时才理会 |
| `WARNING 收到续查（select=N）但没有挂起的会话…` | **要管**：续查没接上上一轮的多选会话。若下一行是 `INFO 续查 … success … 图=…`，说明已自动补救成功，可以忽略 |
| `WARNING 续查按会话键 … 已回退到同会话的最新挂起项 …` | **可忽略**：已知情形（首次查别人、续查是发起人，键里的账号不同），回退后照常出图 |
| `ERROR …'NoneType' object is not iterable` | **要管**：网络完全不通。检查网络 / 代理后重启 |
| `ERROR` + 大段 `Traceback`（含 `update_template`） | **要管**：模板写入等确定性故障，把这段发给维护者 |
| `ERROR` + `Traceback`（含 `Page.goto` / `playwright`） | 渲染阶段失败。通常已自动重试；频繁出现请检查网络 |

> 完整对照与原因分析见 [`DEVELOPMENT.md` §10.6](DEVELOPMENT.md)。

## 7. 已知限制

- **桥接服务必须常驻**。QQ Agent 不会代为启动 Python 进程，关了服务插件就没法工作。
- **第一次查询很慢**（约 1~3 分钟）：要下载 chromium 与 18 MB 舰船图缓存；之后每次 5~10 秒。
- **渲染依赖浏览器**。chromium 装不上时只能拿到文字数据，"出图"功能不可用。
- **图片样式由上游模板决定**，本插件不控制排版。
- **`wws` 后面写什么由上游决定**，本插件只负责转发。
- **数据准确性由 yuyuko 接口负责**，本插件不做二次计算，只把返回的数字原样渲染。

## 附：这个插件是什么定位

- **上游**：[wows-yuyuko/Hikari-core-v2](https://github.com/wows-yuyuko/Hikari-core-v2)
  （Python SDK，GPL）负责取数、套模板、渲染成图。**本插件不含任何战绩数据**。
- **本插件**：在 QQ Agent 里"确定性地认领指令 → 调上游 → 把图发出去 → 把数据交给模型接话"。
- **凭据**：由你在设置页或启动参数提供，只保存在本机。
